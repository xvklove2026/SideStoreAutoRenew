# Project instructions

This is an external-build workspace for a SideStore auto-renew tweak and PreferenceLoader settings bundle. Preserve projectID, kind and buildSystem in apelin-project.json.

Local builds use apelin_project_build with apelin/build.sh; never run the packaging script locally through shell_run. The user explicitly requested a public GitHub repository and GitHub Actions builds, choosing SideStoreAutoRenew on their account. The cloud workflow may call the same script on macOS with Xcode SDK and packaging tools. Repository: https://github.com/xvklove2026/SideStoreAutoRenew. Cloud debs must be installed by the user with their package manager, not passed to apelin_package_install as local artifacts. Do not hard-code a resolved bootstrap path.

0.3.1 is installed and Wi-Fi Health Check is reported all green by the user. Cellular-only cold start was tested on-device: SideStore chose the `pdp_ip0` address `10.42.4.54`, but the 62078 TCP probe was unreachable; the SpringBoard relay's original-socket connect to that address timed out (errno 60), and an independent mobile-process connect did too. A root BPF capture on `pdp_ip0` during the same probe showed no packets; loopback TCP handshake to `127.0.0.1:62078` succeeded. `lockdownd` is running and launchd reports IPv4/IPv6 62078 listener sockets. This points to local cellular-address routing/interface behavior, but does not establish a kernel-level root cause.

An unbuilt 0.3.2 worktree candidate redirects only a local address identified on an active `pdp_ip*` interface to loopback in the SpringBoard relay; Wi-Fi keeps its original destination. SideStore's peer-address check is adjusted for this specific cellular loopback and logs its result. Local build is blocked at unset `SDKROOT`; candidate is not committed, pushed, installed or verified. Next checks: get CI build, install only when requested, verify Wi-Fi all-green regression, cellular TCP/lockdown, Health Check, interface switching, and actual signing expiry. Do not claim cellular success or signing renewal until observed.

Static checks: sh -n apelin/build.sh passed. Preferences/Root.plist, Info.plist and Entry.plist were parsed with icli fs plist. This device's plutil does not accept macOS -lint or -p flags; do not count those invocations as passing checks.

Sources/SRATweak.m runs in SpringBoard and SideStore, using Darwin notification state to send a timestamp and coarse response status. Sources/SRACommon.h owns the preference domain and schedule calculation. Preferences/SRARootListController.m and Root.plist implement time and weekday settings. Vendor contains only minimal MIT-derived Preferences declarations and a link stub, not a toolchain.

The package identifier is com.xx.autosidestore and the package author/maintainer is xx. Keep this identifier consistent across the package, preference domain and logs. Do not change or force-push history unless the user asks.

0.2.3 working tree: apelin/build.sh compiles SRATweak.m + SRACellular.m, not the historical SRADirect/SRARelay modules. SRATweak imports SRACellular.h. SRACellular hooks Network.framework's nw_path_uses_interface_type C interface (not the Swift NWPath value-type wrapper) so a cellular-only path answers true for Wi-Fi policy checks and false for cellular checks. The previous Swift wrapper hook caused SideStore SIGSEGV on iOS 16 due to an incorrect ABI assumption; do not reuse it. The old CoreTelephony data toggles, shortcut URL interception, SpringBoard recovery watchdog and persistent cellular marker remain removed; actual route and pairing remain untouched. Package id com.xx.autosidestore, author xx. Local build remains blocked at missing SDKROOT; 0.2.3 has not been cloud-built or runtime-tested. Do not claim it removes VPN requirements or proves signing renewal.
